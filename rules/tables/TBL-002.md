## Rule

When a column's header sorts the table, make the sort a button or link inside the header cell that works from the keyboard. Expose the sorted column's order in code, ascending or descending, so the direction is never shown by an arrow icon alone.

## Why

A heading that sorts when clicked is a control, even if it looks like text. A keyboard user cannot reach a header cell with a click handler, and a screen reader announces it as a column heading, not as something to press. And when an arrow is the only sign of the order, a person who cannot see it does not know whether the fastest runner is at the top or the bottom.

Three criteria make this a requirement. [WCAG 2.2, 2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard) asks that sorting works from the keyboard. [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value) asks that the control has a role and a name in code. [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships) asks that what the arrow tells sighted people is in the code too. A button or link inside the `th` meets the first two and keeps the cell a header, which TBL-001 needs. The order can be given with `aria-sort` on the sorted column's `th`, or as text inside the control. The criteria do not choose between them. [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG22/#non-text-content) supports the rule: an arrow that shows the order carries information, and once the order is in code, the arrow is decoration and needs no text of its own. The criteria do not ask that sorting is offered in the header at all; a product can offer it elsewhere, such as in a *Sort by* select.

## Do

- A club's page *Spring 10k results* has the columns *Runner*, *Club*, *Finish time* and *Age group*. *Club* and *Finish time* can be sorted. Each of their `TableHead` cells holds a shadcn `Button variant="ghost"` with the heading as its text and an icon after it. *Runner* and *Age group* hold plain text. Using a `button` rather than a link is our own choice; a link that loads the sorted page, such as `?sort=time`, meets the rule too.
- With TanStack Table, set `aria-sort` on the `TableHead` from `header.column.getIsSorted()`: `"asc"` gives `aria-sort="ascending"`, `"desc"` gives `"descending"`, and `false` gives no attribute. Put `onClick={header.column.getToggleSortingHandler()}` on the button, not on the cell. Our own advice: use `aria-sort` rather than text in the button, so the button's name stays "Finish time" whatever the order.
- Set `aria-sort` on one column at a time, and remove it from a column when another one is sorted.
- The page opens sorted by *Finish time*, fastest first. That column already has `aria-sort="ascending"` and an up arrow when the page loads.
- Our own advice: change the icon with the state, such as lucide's `ArrowUp` for ascending, `ArrowDown` for descending and `ArrowUpDown` for a sortable column that is not sorted. Give the icon `aria-hidden="true"`, since `aria-sort` already carries the order.
- If a third press clears the sort, remove `aria-sort` and show the unsorted icon again. Whether the product offers that third press is its own choice.
- Our own advice: keep focus on the same button while the rows re-render, so the next Enter reverses the order and the next Tab goes on from there. Keep a stable `key` on the header cells, so React does not replace the button that has focus.
- Our own advice, beyond the rule: say the new order in a status message, such as "Sorted by finish time, fastest first", as FBK-004 describes.
- When a narrow layout turns the table into a list, offer the sort as a select with the visible label *Sort by* (FRM-001). Its chosen value then shows and exposes the order.

## Don't

- Put `onClick` on the `TableHead` or on a `div` inside it, so the sort works only with a pointer.
- Give the `th` itself `tabIndex={0}` and `role="button"`. The cell stops being a header, and TBL-001 is broken.
- Show the same `ArrowUpDown` icon on *Finish time* whether it is sorted or not, with no `aria-sort`.
- Give the button the `aria-label` "Sort by finish time". This is our own advice: the name contains the visible words, so ACT-001b is met, but it adds an instruction that is read out on every visit while `aria-sort` already says how the column is sorted. Keep the name to the visible heading.
- Put `aria-sort` on the button instead of the header cell.
- Rebuild the header row after each sort so focus drops to the start of the page.

## Exceptions

- **A sortable column that looks plain at rest.** The rule does not ask that a column that can be sorted shows it before the person hovers or focuses it. Showing a sign at rest is a design choice. Once a column is sorted, its state shows and is in code.
- **Several sort columns at once.** Sorting by more than one column at once is outside this rule.
- **Neighbouring rules.** The header cells themselves are TBL-001. Keyboard operation and the focus indicator in general are KBD-001, and this rule is the table case with the state added. The button's role is ACT-009, its name ACT-001b, and an announcement of the new order is FBK-004.
