## Rule

In a dialog that asks the person to confirm a destructive action, give the destructive button the danger style, even when the person has just asked for that action. Its label still names the action, as DLG-003 says, so colour is never the only sign of danger.

## Why

A red button says "stop and look" before the words are read. In a confirmation dialog that is the last chance to notice that the wrong project, the wrong person or the wrong file is about to go. Colour alone is not enough, though. Some people cannot tell red from other colours, some use a high contrast mode that replaces it, and a screen reader does not announce it. The label has to carry the same meaning, which is why this rule leans on the naming in DLG-003. [WCAG 2.2, 1.4.1 Use of Color](https://www.w3.org/TR/WCAG22/#use-of-color) does not ask for a red button. It does mean that if the red signals danger, something else must signal it too, and the label is that something. The text on a red button must also be easy to read against it, under [1.4.3 Contrast (Minimum)](https://www.w3.org/TR/WCAG22/#contrast-minimum).

## Our reasons

The judges are split on this, so we chose. We use the danger style on every destructive confirmation, also when the person asked for the action, for three reasons.

- **A last warning before a loss.** Asking for something and seeing what it will do are not the same. The person chose *Delete* a moment ago, perhaps on the wrong row. The colour is one more cue at the only point left where that slip can be caught. Once the action has run, there is nothing left to warn about.
- **One colour, one meaning.** Justified's `Button` has a `destructive` variant for actions that destroy something. The confirmation dialog is where that action finally runs. Leaving the variant out there would weaken its meaning in the one place it matters most.
- **The label carries the meaning anyway.** The colour is an extra for those who can see it. People who cannot get the same warning from the words *Delete project*, so nobody depends on the red alone.

## Do

- In "Delete the project Autumn 2026?", *Delete project* uses `variant="destructive"` and *Cancel* uses `variant="outline"`.
- The person picks *Delete* on a row in a list of invoices, and a dialog asks "Delete invoice 2026-0412?". *Delete invoice* is red, even though they asked for it.
- Let the title and the button name the same action, so the warning is in the words as well as the colour.
- Use Justified's destructive tokens as they are. The contrast of the button's text against its red is tested in the light and the dark theme. If you change the colours, check the text again against 1.4.3, as VIS-001 describes, and keep each token on the fill it was made for, as VIS-002 asks.
- Add an icon such as a bin next to the label if you like. The text still carries the meaning; the icon is an extra.

## Don't

- Show a red button labelled *OK* or *Yes*. The colour warns, but the words do not say of what.
- Draw *Delete project* in the same style as *Save* because the person asked for it.
- Make *Cancel* red, or use red for an action that destroys nothing, such as *Send*. Red that shows up everywhere stops warning.
- Style *Cancel* as the main, filled button to steer people away from deleting. Focus starts on it, as DLG-004 says, but that is a safe place to start, not an answer chosen for them.
- Signal the danger only with a red border or a red icon, with no words that say what will be lost.
- Fade or tint the red button while it can be pressed, so the danger style is only half there. How readable its text stays is VIS-001. While it is unavailable, for example until the project's name is typed as DLG-003 describes, the faded look of a disabled `Button` is fine, and ACT-005 says what text goes before it.

## Exceptions

- **Actions the person asked for.** These are not an exception. They are the case this rule is written for.
- **Actions that can be undone.** When an action can be undone at once and no dialog is shown, this rule does not apply.
- **Labels and focus.** What the buttons say is covered by DLG-003. The red button never takes focus when the dialog opens, as DLG-004 says.
