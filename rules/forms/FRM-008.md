## Rule

At every step of signing in, let user name, password and code fields take a pasted value in one go and be filled by the browser or a password manager, ask for selected characters of a secret only if another route needs no such step, and give any other test, such as a CAPTCHA, a route without a test.

## Why

Remembering a password, copying a six-digit code from a phone or reading warped letters is hard for many people, and very hard for people with memory, reading or attention difficulties. A password manager and paste take that work away, but only if the page lets them. When one step in the flow blocks them, the whole account is out of reach, however easy the other steps are. [WCAG 2.2, 3.3.8 Accessible Authentication (Minimum)](https://www.w3.org/TR/WCAG22/#accessible-authentication-minimum) requires that every step offers either a route with no such test or a way through it, such as paste or a password manager. Marking the fields so that browsers know what they are for, as [1.3.5 Identify Input Purpose](https://www.w3.org/TR/WCAG22/#identify-input-purpose) and [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value) describe, supports this by letting password managers find the right fields.

## Do

- Give the sign-in fields "Email address" and "Password" visible labels and the tokens `autocomplete="username"` and `autocomplete="current-password"`, so a password manager fills both in one action.
- Ask for a one-time code in a single field labelled "One-time code" with `autocomplete="one-time-code"` and `inputmode="numeric"`. A pasted "482913" goes in whole. The keypad is the guideline FRM-014a, and the field stays a text input, as the guideline FRM-014b says.
- If the design shows six boxes for the code, let a paste or an autofill into any box spread all six digits across them.
- Strip spaces and dashes from a pasted code, so "482 913" from a text message still works.
- Offer a route with nothing to remember or copy where you can: a passkey, a sign-in link sent by email ("Send me a sign-in link"), a QR code scanned with an e-identification app the person already uses, or a prompt to confirm on a phone they are already signed in on.
- Make "Forgotten your password?" lead somewhere that needs no recall. One option: mail a single-use link that stops working after half an hour, and tell the person where it went: "We have sent a link to k•••@example.com. It works for 30 minutes."
- If you need protection against bots, use a check that runs without asking anything of the person, or offer a route past the test, such as the sign-in link.
- If a step asks for something from memory, such as the answer to a security question, let that field take paste and a password manager just like the password field.

## Don't

- Block paste on the password field with `onpaste="return false"`, or use `autocomplete="off"` or a script to keep the browser or a password manager from filling the fields.
- Ask for the last four characters of the password and offer no other route. A password manager cannot fill part of a secret, and a pasted password no longer fits.
- Split a code into six boxes where a paste fills only the first one.
- Ask people to type the letters in a warped image, and offer as the only other choice an audio clip whose letters must also be typed.
- Put a maths question such as "What is 7 + 4?" or a slider puzzle in front of the sign-in button.
- Show a test only after three failed attempts and give no route around it. A test that appears now and then still counts.
- Our own position, beyond what 3.3.8 requires: don't make a security question such as "What was the name of your first pet?" the only way to recover an account, even if its field takes paste. People forget these answers as easily as passwords.

## Exceptions

- **Where the rule applies.** Every step counts: the user name, the password, a second factor and the flow for a lost password or user name. Paste in fields outside sign-in is the guideline FRM-017.
- **The password itself.** Asking for a password is a test of memory, and that is allowed. What makes it pass is the first part of the rule: the field takes paste and a password manager.
- **Creating an account.** This rule covers signing in to an account that already exists. A "Confirm password" field that asks for a new, hidden password twice is allowed; [WCAG 2.2, 3.3.7 Redundant Entry](https://www.w3.org/TR/WCAG22/#redundant-entry) leaves room for it. It still helps to let those fields take paste and a generated password from a password manager, as the guideline FRM-017 asks.
- **Details people know.** Asking for a name, an email address or a phone number is not a memory test.
- **Recognising objects.** At Level AA, a test that only asks people to recognise common objects is allowed without another route.
- **Picking their own content.** At Level AA, a test that asks people to pick out an image, a recording or other non-text content they gave the site, such as the profile photo they uploaded, is allowed without another route. A typed answer about themselves is text and is not covered.
- **Codes sent to another device.** The page has to accept a pasted code. Getting the code from the phone to the clipboard is not the page's job.
- **Clearing and masking.** Emptying the password field after a failed attempt is fine, as long as paste or a password manager can fill it again. A masked field is fine too. Whether to offer a control that shows the password is outside this rule.
- **Related rules.** Every field here still needs a visible label (FRM-001), and a wrong password or code is shown as set out in FRM-002a and FRM-002b. Autocomplete values for fields about the person, such as name and address, are covered by FRM-007.
